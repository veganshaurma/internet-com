# Техническое задание на разработку корпоративного сайта для ООО «Интернет Ком»

## 1. Общая информация о проекте

**Заказчик:**  
Общество с ограниченной ответственностью «Интернет Ком»  
**Англоязычное наименование:** Internet Com LLC

**Домен сайта:**  
`inter-com.online`

**Формат сайта:**  
Статический корпоративный сайт без серверной части, с размещением на GitHub Pages.

**Основная задача сайта:**  
Создать двуязычный корпоративный сайт IT-компании, который:
- формирует доверие к компании;
- понятно и структурированно презентует услуги;
- демонстрирует профессиональный профиль компании;
- содержит карьерный раздел с вакансиями;
- предоставляет контактные данные;
- соответствует требованиям SEO;
- имеет современный, строгий и деловой визуальный стиль.

**Языки сайта:**
- русский — по умолчанию;
- английский — вторая полноценная версия сайта.

---

## 2. Технологические ограничения и требования к реализации

### 2.1. Общие технические требования

Сайт должен быть реализован как **статический сайт**, пригодный для публикации на **GitHub Pages**.

Допускается использование:
- HTML5;
- CSS3;
- JavaScript без backend-логики;
- статического генератора сайта по выбору разработчика (например, Astro, Hugo, Jekyll, 11ty или аналог), если это не усложняет поддержку;
- сборщика фронтенда при необходимости.

Не допускается:
- обязательная серверная часть;
- CMS;
- база данных;
- формы, реально отправляющие данные на сервер;
- обязательная интеграция с backend API.

### 2.2. Хостинг и публикация

Разработчик должен предусмотреть:
- корректную структуру проекта для деплоя на GitHub Pages;
- инструкции по публикации;
- корректную работу относительных путей;
- работу сайта по домену `inter-com.online` после привязки custom domain;
- настройку `404.html` при необходимости;
- наличие `CNAME` для GitHub Pages.

### 2.3. Производительность

Сайт должен быть легким и быстрым:
- высокая скорость загрузки;
- минимальный объем JavaScript;
- оптимизированные изображения;
- корректная работа на десктопе, планшете и мобильных устройствах;
- соответствие современным требованиям производительности на базовом уровне.

---

## 3. Позиционирование и общая концепция

Сайт должен создавать впечатление:
- надежной IT-компании;
- организованного и зрелого подрядчика;
- команды, способной выполнять разработку, тестирование, аналитические и архитектурные работы;
- компании, с которой безопасно и удобно работать в B2B-сегменте.

Тон коммуникации:
- деловой;
- спокойный;
- без излишне рекламных формулировок;
- с упором на компетентность, прозрачность процессов и качество исполнения.

## 4. Дизайн-система сайта

### 4.1. Общий визуальный принцип

Дизайн сайта должен быть реализован как строгая корпоративная дизайн-система для IT-компании, ориентированная на доверие, читаемость, деловую подачу и ощущение зрелого подрядчика.

За основу берется визуальный подход, близкий к референсу `https://t1.ru/`:
- светлая базовая среда;
- крупная современная типографика;
- синий / голубой технологический акцент;
- большие контентные блоки;
- карточная подача услуг и направлений;
- акцент на структуре, а не на декоративности;
- минималистичная графика;
- уверенная деловая подача без визуальной перегрузки.

### 4.2. Принцип использования дизайн-системы

Все страницы сайта должны собираться из единых UI-принципов:
- общей сетки;
- типографической шкалы;
- цветовых токенов;
- системы отступов;
- набора стандартных компонентов;
- единых состояний интерактивных элементов;
- общих правил для карточек, форм, кнопок и навигации.

Разработчик должен реализовать дизайн не как набор разрозненных страниц, а как единую систему переиспользуемых элементов.

#### 4.3.1. Базовая палитра

**Основной фон страницы**

**Фон альтернативных секций**
- `#FFFFFF` — основной белый фон карточек и ключевых блоков
- `#EEF4FA` — мягкий светло-голубой фон для выделенных секций
- `#F1F3F6` — нейтральный светло-серый фон для подложек

**Основной текст**
- `#0F172A` — основной темный текст
- `#1E293B` — подзаголовки и вторичный основной текст
- `#475569` — вторичный текст
- `#64748B` — служебный текст, подписи, метаинформация

**Линии и границы**
- `#D9E2EC` — стандартные границы
- `#C7D2E0` — усиленные границы
- `#E5EAF1` — деликатные разделители

#### 4.3.2. Акцентная палитра

**Primary brand**
- `#0B5FFF` — основной корпоративный акцент
- `#0047CC` — hover / pressed для primary-элементов
- `#3B82F6` — дополнительный технологичный акцент
- `#38BDF8` — голубой вспомогательный акцент

**Accent background**
- `#EAF2FF` — фон для акцентных плашек
- `#E0F2FE` — фон для мягких голубых выделений

#### 4.3.3. Семантические цвета

**Success**
- `#16A34A` — успешное действие / подтверждение
- `#DCFCE7` — фон успешного статуса

**Warning**
- `#D97706` — предупреждение
- `#FEF3C7` — фон предупреждения

**Error**
- `#DC2626` — ошибка валидации
- `#FEE2E2` — фон ошибки

#### 4.3.4. Правила применения цвета

- Основной фон сайта должен оставаться светлым.
- Яркий синий использовать дозированно: для кнопок, ссылок, активных состояний, отдельных акцентных карточек, иконок и ключевых CTA.
- Не использовать много насыщенных цветов одновременно.
- На одной секции допускается не более 1–2 заметных акцентных цветов.
- Контраст текста и фона должен обеспечивать уверенную читаемость.
- Карточки услуг и вакансий должны строиться преимущественно на белом фоне с нейтральной рамкой и сдержанным hover-эффектом.

### 4.4. Типографическая система

#### 4.4.1. Основной шрифт

Для сайта должен использоваться современный гротеск без засечек.

**Рекомендуемый стек:**
- `Inter`
- fallback: `system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", Arial, sans-serif`

Если разработчик не использует `Inter`, допускается близкий по характеру нейтральный sans-serif, но визуально он должен сохранять деловой технологичный характер.

#### 4.4.2. Вес шрифтов

Использовать ограниченный набор начертаний:
- `400` — обычный текст
- `500` — интерфейсные элементы, метки
- `600` — подзаголовки, акцентные подписи
- `700` — ключевые заголовки и CTA

#### 4.4.3. Типографическая шкала

**Desktop**
- `H1`: `56 / 64 / 700`
- `H2`: `40 / 48 / 700`
- `H3`: `30 / 38 / 600`
- `H4`: `24 / 32 / 600`
- `Lead`: `20 / 32 / 400`
- `Body L`: `18 / 30 / 400`
- `Body M`: `16 / 28 / 400`
- `Body S`: `14 / 22 / 400`
- `Caption`: `12 / 18 / 500`
- `Button`: `16 / 24 / 600`

**Tablet**
- `H1`: `44 / 52`
- `H2`: `34 / 42`
- `H3`: `28 / 36`

**Mobile**
- `H1`: `34 / 42`
- `H2`: `28 / 36`
- `H3`: `22 / 30`
- `Lead`: `18 / 28`
- `Body M`: `16 / 26`

#### 4.4.4. Правила типографики

- Заголовки — короткие, плотные, уверенные.
- Не использовать слишком узкие колонки в hero-блоках.
- Максимальная ширина текстовой колонки для длинных описаний: `720–760 px`.
- Для основного контента использовать комфортную межстрочность.
- Не применять декоративные шрифты.
- Не использовать полностью капс для длинных заголовков.
- Подписи к разделам и метки допускаются в uppercase только точечно.

### 4.5. Система отступов и 8pt grid

#### 4.5.1. Базовая шкала spacing tokens

- `4 px`
- `8 px`
- `12 px`
- `16 px`
- `24 px`
- `32 px`
- `40 px`
- `48 px`
- `64 px`
- `80 px`
- `96 px`
- `120 px`

#### 4.5.2. Правила вертикального ритма

- Между заголовком секции и описанием: `16–24 px`
- Между описанием секции и контентом: `32–40 px`
- Вертикальный padding секции на desktop: `80–120 px`
- Вертикальный padding секции на tablet: `64–80 px`
- Вертикальный padding секции на mobile: `48–64 px`

#### 4.5.3. Правила внутренних отступов

**Карточки**
- desktop: `32 px`
- tablet: `24 px`
- mobile: `20 px`

**Кнопки**
- vertical padding: `14–16 px`
- horizontal padding: `24–28 px`

**Поля формы**
- internal padding: `14–16 px`

### 4.6. Контейнеры и сетка

#### 4.6.1. Контентный контейнер

- максимальная ширина основного контейнера: `1200–1280 px`
- безопасные боковые поля:
  - desktop: `32 px`
  - tablet: `24 px`
  - mobile: `16 px`

#### 4.6.2. Сетка

Использовать адаптивную сетку:
- desktop: 12 колонок
- tablet: 8 колонок
- mobile: 4 колонки

#### 4.6.3. Межколоночные интервалы

- desktop: `24 px`
- tablet: `20 px`
- mobile: `16 px`

#### 4.6.4. Принципы раскладки

- hero-блок — широкая композиция с крупным заголовком и заметным CTA;
- секции услуг — карточки 2–4 в ряд в зависимости от экрана;
- страницы внутренних разделов — с приоритетом на текст, доверительные блоки и ясную иерархию;
- мобильная версия — без горизонтального скролла.

### 4.7. Скругления, тени и границы

#### 4.7.1. Радиусы

- `8 px` — мелкие элементы
- `12 px` — поля формы, secondary-кнопки
- `16 px` — карточки
- `20 px` — крупные карточки и акцентные блоки
- `999 px` — pill-элементы и чипы

#### 4.7.2. Тени

Использовать сдержанные мягкие тени.

**Shadow / card-default**
- `0 8px 24px rgba(15, 23, 42, 0.06)`

**Shadow / hover**
- `0 14px 36px rgba(15, 23, 42, 0.10)`

#### 4.7.3. Границы

- стандартная граница: `1 px solid #D9E2EC`
- активная граница: `1 px solid #0B5FFF`
- для крупных выделенных блоков допускается сочетание белого фона, легкой тени и почти незаметной границы.

### 4.8. Система компонентов

#### 4.8.1. Кнопки

**Primary button**

Назначение:
- основные CTA: «Услуги», «Связаться», «Откликнуться», «Подробнее»

Стили:
- фон: `#0B5FFF`
- текст: `#FFFFFF`
- радиус: `12 px`
- высота: `52–56 px`
- padding: `16 px 28 px`

Состояния:
- hover: `#0047CC`
- active: более глубокий синий
- disabled: светло-серый фон, приглушенный текст

**Secondary button**

Стили:
- фон: `#FFFFFF`
- текст: `#0F172A`
- граница: `1 px solid #C7D2E0`

Hover:
- фон слегка голубовато-серый

**Tertiary / text button**

Стили:
- без плотной заливки;
- синий текст;
- стрелка или лаконичный индикатор перехода допускается.

#### 4.8.2. Ссылки

- основной цвет ссылок: `#0B5FFF`
- hover: `#0047CC`
- подчеркивание — по hover или в текстовых блоках по умолчанию, если это улучшает читаемость

#### 4.8.3. Карточки

Карточки являются одной из основных единиц интерфейса.

Варианты карточек:
- карточка услуги;
- карточка преимущества;
- карточка вакансии;
- карточка этапа работы;
- карточка реквизитов / контактной информации.

Стили:
- фон: белый;
- граница: светлая;
- радиус: `16–20 px`;
- padding: `24–32 px`;
- тень: слабая;
- hover: легкий подъем и усиление тени.

#### 4.8.4. Поля формы

Типы:
- text input
- email input
- textarea
- select
- file input

Стили:
- высота поля: `52–56 px`
- фон: `#FFFFFF`
- граница: `1 px solid #C7D2E0`
- радиус: `12 px`
- текст: `#0F172A`
- placeholder: `#64748B`

Состояния:
- focus: синяя рамка или outline
- error: красная рамка + текст ошибки
- success для карьерной формы можно не использовать, итоговое сообщение показывать отдельным alert-блоком

#### 4.8.5. Сообщения / alert

**Success alert**
- фон: `#DCFCE7`
- текст: `#166534`
- радиус: `12 px`
- padding: `16–20 px`

Использовать для фейковой отправки резюме.

#### 4.8.6. Чипы / метки

Использовать для:
- языка;
- категории услуги;
- типа вакансии;
- статуса секции.

Стили:
- фон: `#EAF2FF`
- текст: `#0B5FFF`
- радиус: `999 px`
- padding: `8 px 12 px`
- размер шрифта: `13–14 px`

### 4.9. Навигация

#### 4.9.1. Header

Шапка сайта должна быть фиксированной или полуприкрепленной при прокрутке.

Состав:
- логотип слева;
- основное меню по центру или справа;
- переключатель языка;
- CTA-кнопка или email-ссылка.

Стили:
- светлый фон;
- нижняя граница или легкая тень при scroll state;
- высота header на desktop: `80–88 px`;
- на mobile — компактная версия с burger-menu.

#### 4.9.2. Footer

Подвал должен быть визуально более плотным, но не темным по умолчанию.

Рекомендуемый стиль:
- фон: `#F1F3F6` или `#0F172A` для контрастного футера
- если фон темный, текстовые токены должны быть инвертированы

Содержимое:
- логотип / название;
- email;
- ссылки на основные разделы;
- юридические страницы;
- реквизиты или краткая ссылка на контакты.

### 4.10. Иконография и графика

#### 4.10.1. Иконки
- outline или полу-outline стиль;
- единая толщина линий;
- без 3D и без иллюстративной перегрузки;
- использовать в услугах, преимуществах, этапах, вакансиях.

#### 4.10.2. Иллюстрации
- абстрактная технологическая графика;
- геометрические формы;
- мягкие градиенты в синей гамме;
- допустимы фоновые blur-элементы и полупрозрачные формы;
- не использовать стоковые изображения как доминирующий визуал.

#### 4.10.3. Фотографии
Если используются фотографии:
- только качественные;
- в деловом B2B-контексте;
- без излишней постановочности;
- в ограниченном количестве.

### 4.11. Motion и интерактивность

Анимация должна быть минимальной и деловой.

Допускается:
- fade-up при появлении секций;
- мягкое изменение тени и вертикального положения карточки на hover;
- плавное раскрытие accordion / FAQ;
- плавная смена языка без тяжелых эффектов.

Не допускается:
- длительные и навязчивые анимации;
- сложные параллакс-эффекты;
- «кричащие» motion-решения;
- анимации, мешающие чтению.

Рекомендуемая длительность:
- `160–240 ms` для hover;
- `240–320 ms` для появления и раскрытия блоков.

### 4.12. Адаптивные правила

**Desktop**
- максимальная полнота композиции;
- крупный hero;
- карточки в 3–4 колонки;
- полная навигация в шапке.

**Tablet**
- упрощение сетки;
- hero становится более вертикальным;
- карточки 2 в ряд;
- сокращение второстепенных элементов.

**Mobile**
- одна колонка как базовый паттерн;
- компактный header;
- крупные tappable-элементы;
- кнопки и поля не менее `44 px` по интерактивной высоте;
- тексты не должны визуально «слипаться».

### 4.13. Доступность

Нужно соблюдать базовые требования accessibility:
- достаточный контраст;
- видимый focus-state;
- корректные label для формы;
- логичная tab-навигация;
- alt-тексты у изображений;
- семантическая разметка заголовков и секций.

### 4.14. Дизайн-токены для передачи в разработку

Разработчик должен оформить базовые токены в явном виде, например через:
- CSS custom properties;
- SCSS variables;
- JSON design tokens;
- theme config, если используется фреймворк.

Минимальный набор токенов:
- colors
- typography
- spacing
- radius
- shadows
- breakpoints
- container widths
- component states

Пример структуры:
- `--color-bg-default`
- `--color-bg-muted`
- `--color-text-primary`
- `--color-text-secondary`
- `--color-primary`
- `--color-primary-hover`
- `--space-2`
- `--space-3`
- `--radius-md`
- `--shadow-card`
- `--font-size-h1`

### 4.15. Обязательные UI-компоненты для реализации

В рамках дизайн-системы должны быть отдельно продуманы и стилистически унифицированы:
- header;
- footer;
- language switcher;
- primary / secondary buttons;
- text links;
- section heading block;
- service card;
- vacancy card;
- contact card;
- info badge / chip;
- form fields;
- success message;
- legal page layout;
- breadcrumbs или page intro block для внутренних страниц.

### 4.16. Запреты и ограничения по стилю

Не использовать:
- кислотные цвета;
- тяжелые темные интерфейсы как основное решение;
- пестрые градиенты;
- слишком мелкую типографику;
- декоративные шрифты;
- перегруженные фоны;
- стеклянные эффекты как основу интерфейса;
- агрессивную продажную стилистику;
- визуальные решения, создающие ощущение шаблонного дешевого сайта.

- заказная разработка;

- QA services;
- software development;
- IT consulting;
- technical documentation;
- solution architecture;
- frontend development;
- backend development.
